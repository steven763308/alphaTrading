# Architecture

```
Browser (React, Next.js App Router)                 Next.js server (single Node process)
─────────────────────────────────────               ───────────────────────────────────────────────
Simulator ─ CandleChart (lightweight-charts)  ──►   /api/sessions/*   ─► services/backtest ─┐
          ─ OrderTicket (sizing, client-side)       /api/live/*       ─► services/live ─────┤
          ─ TradesPanel                             /api/live/stream  ◄─ live/feed (SSE)    │
Journal   ─ table + drawer + annotation chart       /api/journal/*    ─► repo/journal       ├─► engine (pure TS)
Analytics ─ KPIs + Recharts                         /api/analytics    ─► analytics/metrics  │
Settings  ─ settings, strategies, CSV import        /api/settings …                         │
                                                                                            ▼
                                                    repo/* (Drizzle) ─► SQLite (WAL) data/tradelab.db
                                                    market/binance ─► data-api.binance.vision (REST)
                                                    live/feed      ─► data-stream.binance.vision (WS)
```

## Folders

| Path | Responsibility |
|---|---|
| `src/lib/engine/` | **Pure** execution engine: types, price math, sizing, order/position lifecycle, commands. Shared by replay, live, tests, and the browser (sizing preview). |
| `src/lib/analytics/` | Pure statistics over journal rows (win rate, PF, expectancy, R, drawdown, groupings, sample-size warnings). |
| `src/lib/market/` | `MarketDataProvider` interface, Binance implementation, CSV parser, timeframe helpers. |
| `src/lib/server/db/` | Drizzle schema, client (auto-migrates on start), idempotent seed. |
| `src/lib/server/repo/` | **Repository layer.** All SQL lives here. Services never touch tables directly, so a PostgreSQL implementation can replace these modules. |
| `src/lib/server/services/` | Backtest sessions, live commands, market data caching, CSV import. |
| `src/lib/server/live/feed.ts` | Live feed manager: WebSocket, segments, staleness, reconnect, REST reconciliation. |
| `src/app/api/` | Thin route handlers: Zod validation → service → JSON. |
| `src/components/` | UI. |
| `drizzle/` | SQL migrations (generated by `drizzle-kit`). |
| `tests/` | Vitest suites + real Binance fixtures. |

## Data model (13 required tables + 2 support)

`instruments`, `market_data_sources`, `market_data_datasets`, `candles`, `strategies`, `backtest_sessions`, `paper_accounts`, `orders`, `executions`, `positions`, `trade_journal`, `account_equity_snapshots`, `simulation_events`, plus `live_symbol_cursors` (reconciliation cursor) and `settings`.

- Every backtest session owns a `paper_accounts` row (`kind = backtest`). Live trading uses one `kind = live` account. Orders, positions, and executions always reference an account, so both modes share one code path.
- Orders → positions (1 position per filled entry order) → executions (entry + exit). These are separate entities.
- `candles` is keyed `(dataset_id, time)`. Exchange data is cached in an append-only dataset per symbol/timeframe (closed candles are never rewritten). Each CSV import is its own immutable dataset.
- Sessions pin `dataset_id`, `data_version`, and a SHA-256 checksum of the replayed candles, plus `initial_cursor_time` and `cursor_time`.
- All timestamps are UTC epoch milliseconds and are converted to the display time zone only in the UI.

## Performance choices

- The browser holds only what the chart shows (initially 1,500 bars) and pages older history on scroll (`before=` cursor). Multi-year minute data stays in SQLite.
- Replay advances in batches (up to 500 bars per request) at high playback speeds, with one SQLite transaction per request.
- Database writes happen only on state changes: cursor/revision per step, plus orders, executions, journal, and snapshots when something actually fills. Equity snapshots are written on realized events, not every bar.
- Live: the engine runs only for symbols with exposure. The processing cursor is written every 15 s and on each closed minute.

## Extending

- **New data provider:** implement `MarketDataProvider` (`fetchCandles`, `fetchRecent`, `symbolInfo`, optional `openStream`) and register it in `services/market-data.ts`.
- **PostgreSQL:** add a `pg-core` schema mirror and Postgres versions of `repo/*`. Services and the engine stay unchanged.
